# 語音燈泡控制台

可放上 GitHub Pages 的 RWD 靜態網頁。開啟頁面後會自動連接 EMQX 公開測試伺服器；按 B1、B2、B3，或啟動語音辨識並說出「幫我打開燈泡1／2／3」，就會把對應內容發布到 MQTT 主題 `w6`。

## 使用方式

1. 用支援 Web Speech API 的瀏覽器開啟網站，等待右上方狀態顯示「已連線」。
2. 手動操作：修改任一張卡片的「發送內容」，按「發送 B1／B2／B3 到 w6」。修改的內容會保存在目前瀏覽器。
3. 語音操作：按「開始語音控制」，允許麥克風權限，然後說「幫我打開燈泡1」、「幫我打開燈泡2」或「幫我打開燈泡3」。再按一次可停止聆聽。
4. 在 MQTTX 使用 `broker.emqx.io:1883` 訂閱 `w6`，可查看網頁發出的內容。

預設發送內容是三句語音指令原文。如果接收燈泡的裝置需要 `1`、`2`、`3` 或其他格式，直接修改三個內容框即可；語音口令不變。

## 為什麼網頁使用 8084？

MQTTX 是桌面應用程式，可以用原生 MQTT/TCP 連接 `broker.emqx.io:1883`。瀏覽器中的 MQTT.js 需要 WebSocket，所以本頁連接同一台伺服器的 `wss://broker.emqx.io:8084/mqtt`。兩種連線方式都能發布或訂閱同一個 `w6` 主題。

## GitHub Pages

將 `index.html`、`styles.css` 和 `app.js` 放在儲存庫根目錄，於儲存庫 **Settings → Pages** 選擇從預設分支的 `/ (root)` 發布。網站應使用 HTTPS，才能正常要求麥克風權限並連接加密的 WebSocket。

## 注意

- `broker.emqx.io` 與 `w6` 是公開測試環境；請勿傳送密碼或機密內容。
- 語音辨識需要瀏覽器支援，且通常需要網路連線。若內建瀏覽器顯示服務連線失敗，請用 Chrome 直接開啟 GitHub Pages 網址；手動按鈕仍可使用。
- MQTT QoS 為 0；畫面上的「已發送」表示瀏覽器已嘗試發布，不能保證接收裝置已執行動作。
- MQTT.js 由 `https://unpkg.com/mqtt@5.16.0/dist/mqtt.min.js` 載入，因此首次開頁需要能連上該 CDN。
